## 🚀 Руководство по запуску

### Предварительные требования
- **Go:** 1.24+ (проверено на Go 1.27)
- **Node.js:** 18+ (проверено на Node.js 24)
- **npm:** 10+

---

### Шаг 1. Запуск Backend (Go)

```powershell
# Перейдите в папку backend
cd backend

# Локальный запуск (по умолчанию использует встроенную SQLite БД defect_management.db)
go run cmd/api/main.go
```
*Или запустите заранее скомпилированный бинарник:*
```powershell
.\bin\api.exe
```
API будет доступно по адресу `http://localhost:8080`. При первом запуске база данных автоматически создаст таблицы и заполнит сиды.

*(Опционально для PostgreSQL):*
```powershell
docker compose up -d postgres
# В backend/.env укажите:
# DATABASE_URL=postgres://postgres:postgrespassword@localhost:5432/defect_management?sslmode=disable
```

---

### Шаг 2. Запуск Frontend (React)

```powershell
# Перейдите в папку frontend
cd frontend

# Установка зависимостей (с флагом разрешения peer dependencies)
npm.cmd install --legacy-peer-deps

# Запуск в режиме разработки
npm.cmd start
```

Приложение откроется на порту `3000`: [http://localhost:3000](http://localhost:3000).

## 🧪 Сценарии проверки функционала

### 1. Публичный пользователь
1. Откройте [http://localhost:3000](http://localhost:3000).
2. **Отслеживание заявки:**
   - В поле поиска введите номер заявки `1` (или `6`) и нажмите поиск.
   - Отобразится статус, хронология изменения статусов и прикрепленные фотографии.
3. **Создание новой заявки:**
   - Нажмите кнопку **"Создать заявку"**.
   - Выберите объект, категорию, уровень критичности, введите описание и email (минимум 5 символов до `@`, например `test@test.ru`).
   - Прикрепите фото или видео дефекта.
   - Нажмите **"Отправить заявку"** — система автоматически рассчитает приоритет (1–10) с учетом правил ТЗ и перенаправит на страницу отслеживания с кодом заявки.

### 2. Кабинет менеджера
1. Перейдите на [http://localhost:3000/login](http://localhost:3000/login).
2. Введите `admin@a.a` / `admin123`.
3. **Вкладка "Заявки" (DataGrid):**
   - Просмотр всех 10 предустановленных заявок.
   - Сортировка по колонкам (ID, приоритет, дата, статус).
   - Фильтрация по статусу, объекту, приоритету.
   - Для статуса `новый` — действие **"Принять в работу"** (переводит в `в работе`).
   - Для статуса `в работе` — действие **"Отметить как выполненную"** или **"Отклонить с указанием причины"** (открывает модальное окно ввода причины).
4. **Вкладка "Объекты":**
   - Список строительных комплексов с адресами и количеством заявок.
   - Создание нового объекта и редактирование существующих.
5. **Вкладка "Аналитика" (Дашборд):**
   - Круговая диаграмма (PieChart) распределения заявок по 4 статусам.
   - Столбчатая диаграмма (BarChart) заявок по строительным объектам.
   - Гистограмма трендов подачи заявок по времени суток.
